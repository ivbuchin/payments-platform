# ADR-0001. Границы сервисов и общение между ними

**Статус:** принято

## Контекст

Платформа делится на деньги (wallet), бизнес-процесс платежа (payments) и уведомления (notifications).
Нужно, чтобы сервисы развивались и падали независимо.

## Решение

- **Database per service:** у каждого сервиса своя БД (`wallet`, `payments`, `notifications`) в одном инстансе PostgreSQL. Чужие таблицы не читаем.
- **Синхронно** (HTTP) — только там, где нужен немедленный результат: payments → wallet. Вызовы идемпотентны.
- **Асинхронно** (RabbitMQ, topic-exchange `pp.events`) — всё, что не блокирует ответ клиенту: уведомления.
- Контракты событий — в `libs/contracts`; правило совместимости: поля только добавляются, несовместимое изменение — новый тип события.
- Общий код — только инфраструктурный (`nest-kit`, `outbox`); доменная логика не шарится.

## Последствия

- Недоступность notifications не влияет на платежи; события копятся в outbox.
  − Нет распределённых транзакций: согласованность достигается идемпотентностью и повтором (ADR-0003, ADR-0004).
